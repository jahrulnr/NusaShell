# Description examples

Good descriptions say what and when in third person:

```yaml
description: Summarize support tickets into action items. Use when the user asks for a ticket digest or triage summary.
```

```yaml
description: Review TypeScript changes for correctness and security. Use when the user asks for code review, regression analysis, or a PR checklist.
```

Avoid vague labels such as `Helpful skill` or descriptions that only list an
implementation detail. Keep trigger terms natural and avoid promising tools the
skill does not provide.
